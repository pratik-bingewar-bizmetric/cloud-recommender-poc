## 1. Executive Summary & Root Cause Diagnosis

The Token Economics module provides FinOps visibility into generative AI workloads by tracking prompt and completion token consumption, calculating model-specific costs, and identifying unattributed requests across cloud scopes.

During our end-to-end investigation and live API tracing against Azure Monitor (`Microsoft.CognitiveServices/accounts`), three distinct root causes were identified and resolved:

> [!IMPORTANT]
> ### 1. Metric Name Discrepancy & Actual Supported Names
> Microsoft's official supported Azure Monitor platform metric names for Azure OpenAI inference are:
> - **`ProcessedPromptTokens`**: Total prompt (input) tokens processed by the deployment.
> - **`GeneratedTokens`**: Total completion (output) tokens generated by the deployment (NOT `ProcessedCompletionTokens`).
> - **`TokenTransaction`**: Total inference tokens processed (`ProcessedPromptTokens + GeneratedTokens`).
> - Additionally, model-level usage metrics include **`InputTokens`**, **`OutputTokens`**, and **`TotalTokens`**.
>
> In the original code, `InputTokens,OutputTokens,TotalTokens` were queried against resources that emitted `ProcessedPromptTokens,GeneratedTokens,TokenTransaction`, or vice-versa. Querying the unified set `"ProcessedPromptTokens,GeneratedTokens,TokenTransaction,InputTokens,OutputTokens,TotalTokens"` with `api-version=2023-10-01` ensures full compatibility across all Azure OpenAI deployments.

> [!IMPORTANT]
> ### 2. Timespan URL Query Encoding (`+00:00` vs. `Z`)
> When `timespan` was passed as `f"{start_time.isoformat()}/{end_time.isoformat()}"`, Python produced timestamps with the offset `+00:00` (e.g. `2026-09-21T12:05:02+00:00`).
> During HTTP request transmission, the `+` character was decoded as a space (` `) by Azure ARM, causing Azure Monitor to reject the request with:
> ```json
> {"code":"BadRequest","message":"Detected invalid time interval input: 2026-09-21T12:05:02 00:00/2026-10-21T12:05:02 00:00, supported Iso 8601 time interval format: (Datetime/Datetime, Datetime/Duration, Duration/Datetime, Duration)"}
> ```
> Formatting timestamps with the standard UTC `Z` suffix (`start_time.strftime("%Y-%m-%dT%H:%M:%SZ")`) resolved this defect completely, yielding immediate HTTP 200 responses with active datapoints.

> [!IMPORTANT]
> ### 3. Multi-Resource Subscription Scope Iteration
> The original implementation only probed `ai_resources[0]`. If `ai_resources[0]` happened to be an idle or uninstrumented account (such as `smart-expense-ai-bizmetric`), the entire subscription was reported as having no telemetry, even though other AI accounts in the same subscription (such as `rg-telecom-rag-poc`, `pratikbingewar-5556-resource`, and `rg-cloud-recomender`) were actively generating token telemetry.
> The updated service iterates across all discovered AI resources in the subscription, aggregating metrics without double-counting.

### 2.1 Azure Monitor Platform Metrics (Active Implementation)
- **Endpoint:** `GET https://management.azure.com/{resourceId}/providers/microsoft.insights/metrics`
- **Supported Metric Names:** `ProcessedPromptTokens`, `GeneratedTokens`, `TokenTransaction`, `InputTokens`, `OutputTokens`, `TotalTokens`.
- **API Version:** `2023-10-01`
- **Granularity:** Sampled per-minute, rolled up to hourly (`PT1H`) or daily (`P1D`).
- **Required Azure IAM Role:** `Monitoring Reader` or `Reader` on the target Cognitive Services account or subscription.
- **Characteristics:** Zero configuration required on customer resources; automatically emitted by Azure for all inference calls.
- **Double-Counting Prevention:** `TokenTransaction` represents `ProcessedPromptTokens + GeneratedTokens`. The calculation engine takes `res_total = res_transaction if res_transaction > 0 else (res_prompt + res_completion)`. Individual metrics are never added to the total transaction metric.
