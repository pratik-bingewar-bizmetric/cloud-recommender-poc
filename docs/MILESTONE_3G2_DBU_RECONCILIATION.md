## 3. Root Cause of the Reported 7.28 DBU Discrepancy

In Milestone 3G.1, the report author wrote:
- SQL Compute: 19,172.73 DBU
- Interactive Clusters: 11,181.82 DBU
- Automated ETL Jobs: 51,072.73 DBU
- Model Serving: 7,000.00 DBU
- Sum: $19,172.73 + 11,181.82 + 51,072.73 + 7,000 = 88,427.28\text{ DBU}$
- Variance against 88,420 total: **+7.28 DBU**

### Forensic Trace of the Authoring Error
1. **Rough Quotient Approximation:**  
   The 3G.1 author did not read the exact `usage_qty` fields from the 24 ledger items. Instead, they took the dollar amounts and divided them by theoretical retail list rates:
   - $\$42,180 / \$2.20 = 19,172.7272... \approx 19,172.73\text{ DBU}$
   - $\$24,600 / \$2.20 = 11,181.8181... \approx 11,181.82\text{ DBU}$
   - $\$74,080 / \$1.45048... \approx 51,072.73\text{ DBU}$
   - Rounded Model Serving to $7,000\text{ DBU}$.
2. **Omission of Databricks Apps:**  
   The 3G.1 narrative completely forgot the **310.0 DBU** consumed by Databricks Apps ($1,240.00).
3. **Conclusion:**  
   The actual source code, database tables, and ledger objects never contained a 7.28 DBU discrepancy. The variance was purely an authoring artifact in the 3G.1 report document.
